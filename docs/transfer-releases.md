Transfer uses its own transfer/version.go, transfer/vX.Y.Z tags and bitspeed-transfer archive names. Inspect keeps its existing independent version and release. Version 0.1.0 was selected after independent review, exact-source candidate CI 39391488194 and five clean packaging/three native gates in Release Transfer 39391730821 passed. That 0.0.0-dev run skipped publication. Stable publication must repeat all exact-source gates; a development version cannot publish.

## Platform scope

Linux amd64 and macOS arm64 have native delivery checks on CI local filesystems: preparation, upload, complete digest/publication, receipt caching, process restart and same-ID retry. Separate executable tests kill sender and receiver during a partial chunk, after accepted chunk publication before response delivery and after final publication before its response. Each resumes from the same immutable snapshot with the original source removed, verifies one complete output and a stable receipt, and confirms verified chunk identity was retained. A packaged TLS listener test uses a locally trusted certificate; the Go client test exercises certificate-verified HTTPS delivery and rejection of an unrelated certificate. No insecure mode exists.

Linux arm64 and macOS amd64 are cross-built only; there is no native runtime or filesystem crash coverage for those variants. Windows amd64 is a native executable compatibility archive for version/help and explicit unsupported-operation behavior. Windows snapshot, token-file, send/status CLI and receiver operations remain unsupported. Its native check is not delivery coverage. BUILD_INFO.json and release verification metadata distinguish these limits. Do not recommend Windows for file delivery.

The supported filesystem families and root trust requirements are in receiver-staging.md. Native runner tests do not establish every filesystem/mount/hardware power-loss guarantee. The implementation relies on checked file and directory synchronization and no-replace hard links. Fixed five-minute operation/startup bounds can fail safely on large/slow storage. The 64 GiB manifest bound is a protocol maximum, not a tested throughput or completion-time promise.

## Automated release gate

Release Transfer is triggered only by successful exact-commit main CI. It shares the bitspeed-release concurrency group with Release Inspect. The shared builder in scripts/release_inspect.py selects the product explicitly with --product transfer; the default remains inspect. Five clean CGO-disabled archives are built with the exact go.mod toolchain. All five provenance/package jobs and three native smoke jobs must succeed before the publisher can create or resume a draft. Linux/macOS native gates additionally run executable interruption and TLS smoke checks.

The publisher rechecks exact-source main CI and current HEAD, verifies clean archive provenance, records operational/native/cross-build limits, creates a source-bound immutable product tag and uploads a draft. It downloads every uploaded asset and compares checksums before publishing. A published version is immutable and skipped on later pushes. A failed unpublished tag cannot move to another source; use a fresh version after fixing source. No manual publication is part of the workflow.

To keep releases/latest/download URLs stable, either publisher carries all five archives of the other released tool from previous latest only after validating its SHA256SUMS. An incomplete/corrupt carried set blocks publishing. No other product is rebuilt or relabelled; its embedded provenance remains its own. Every new latest has both released products' archives, one combined SHA256SUMS and the publishing product's verification JSON. Available other-product verification metadata is also checksum-verified and carried forward, preserving existing latest metadata links; immutable tagged releases retain their originals.

Every archive includes the executable, README, Apache license/notice, Transfer reference/retention documentation, BUILD_INFO.json and licensing material from the exact building Go toolchain. The result recorder runs formatting, release guards, vet, repository-wide race tests, both command builds, executable delivery/restart/interruption and TLS checks. Large-file assembly verification measures total Go allocations for a sparse 64 MiB plus 17-byte source and enforces a bound independent of the complete file; recorded values describe that environment, not all maximum-size transfers. Public asset/checksum/download verification is required after automated publication before adding website download links.
