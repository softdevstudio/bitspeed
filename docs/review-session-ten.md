# Final publication review

A separate independent task reviewed the session-ten implementation without the implementation conversation. Scope included three-copy capacity reconstruction, assembly, journal transitions, no-replace publication, witness/receipt recovery, strict client response binding, sender receipt persistence, CLI delivery, crash/fault tests and retention documentation. It ran repository-wide tests and vet, Transfer/CLI race tests and native executable smoke. Final re-review found no remaining blocking findings in session-ten scope.

Review identified a sender retry bug when completed status had missing retained chunks: the client attempted PUT into a completed session. It now accepts the verified matching receipt without retransmitting those chunks. A regression removes retained chunks after completion and proves repeated send still returns the same receipt.

Review identified first-restart failures after safely resetting interrupted finalization to uploading, or recording a durable terminal failure. Status now serves the resulting uploading/failed state; explicit finalize still returns the appropriate mutation error. Tests restart across missing/corrupt output, missing witness, foreign output and durable receipt evidence.

Review also required validating present completion metadata in failed sessions and distinguishing malformed metadata from damaged published output. Every present completion.json is checked against its immutable binding before serving; malformed receipts block recovery. Trustworthy receipt plus missing/damaged published evidence becomes failed storage_corrupt. No output path is adopted from equal bytes alone.

Final review confirmed failed admission retries reject mutation, the post-publication recovery-sync injection occurs after witness verification rather than during the capability probe, and documentation accurately describes conservative three-copy migration and offline retention. No automatic evidence deletion or eviction was added. The native smoke now completes delivery, verifies the digest and cached receipt, restarts receiver/sender processes, compares stable receipts, checks one output and rejects later output damage.

Process tests kill during intent, assembly, ready publication, destination linking, receipt write/rename and completed-journal publication. Fault tests cover short/corrupt/failed writes, close, sync, rename/link, sender receipt persistence, capacity and cancellation. Wire tests reject malformed/forged completion claims. Recorded repository checks retain environment and source fingerprints in test/results. Transfer remains 0.0.0-dev with no release; session-eleven hardening and platform gates still apply. These checks do not establish storage hardware power-loss behavior.
